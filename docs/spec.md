# chameleon（变色龙）— Chrome 会话隔离管理工具 规格说明

> 状态：已确认（grilling 会话决议 + to-spec 合成）。术语见 `CONTEXT.md`，架构决策见 `docs/adr/0001~0003`。

## Problem Statement

手工测试团队需要同时以多个角色（管理员 / 审计员 / 普通用户…）测试同一系统，验证权限差异。现状有两个痛点：

1. **多角色串号**：浏览器只有一份 Cookie/会话，切换角色要反复登出登录；现有靠 bat 脚本开多实例，不可控、不直观，且存在误操作波及日常 Chrome 配置的风险。
2. **跨角色验证重复操作**：验证「同一页面不同角色可见字段差异」时，需要手动复制 URL、在新角色窗口粘贴打开，每次都要重来。

团队为非技术背景，无命令行能力；国内网络环境要求全程离线、零谷歌账号依赖。

## Solution

一个桌面工具：每个测试角色对应一个独立 Chrome 隔离窗口（独立用户数据目录 + CDP 端口），界面用色块区分角色；支持一键启动/关闭所有角色、会话接力（把当前页面 URL 传到另一个角色窗口）、常用 URL 预设、窗口位置记忆。纯本地离线、明文 JSON 配置、便携文件夹搬家即用。

## User Stories

1. 作为手工测试人员，我想为每个角色创建独立的隔离 Chrome 窗口（独立数据目录），以便同时登录管理员/审计员/普通用户而不串号 — v1
2. 作为手工测试人员，我想给角色起自定义中文名（如「ERP-管理员」）并配颜色，以便一眼区分窗口归属 — v1
3. 作为手工测试人员，我想一键启动所有预定义角色窗口，以便快速开始每日多角色并行测试 — v1
4. 作为手工测试人员，我想一键关闭所有测试用 Chrome 窗口，以便测试结束快速清理，且绝不触碰我的日常 Chrome 配置 — v1
5. 作为手工测试人员，我想在角色 A 窗口点击「接力」把当前页面 URL 传到角色 B 的新标签页并聚焦，以便验证同一页面不同角色的可见字段差异 — v1

7. 作为手工测试人员，我想在接力时选择「接力模式」（关闭 A 窗口），以便只保留新角色窗口节省资源 — v1
8. 作为手工测试人员，我想接力到未启动的角色时工具自动先拉起该角色窗口，以便无需手动预开窗口 — v1
9. 作为手工测试人员，我想工具自动检测 Chrome 安装路径，以便开箱即用无需配置 — v1
10. 作为手工测试人员，我想自动检测失败时手动指定 Chrome/Edge 路径，以便非默认安装位置也能用 — v1
11. 作为手工测试人员，我想用 Edge（Chromium 内核）作为备选浏览器，以便环境没有 Chrome 时也能测试 — v1
12. 作为手工测试人员，我想给角色配置常用 URL 预设（如「管理员后台首页」），以便点击即开、无需手输地址 — v1
13. 作为手工测试人员，我想每个角色窗口记住上次位置与大小，以便启动时自动排列、不用手动拖拽对齐 — v1
14. 作为手工测试人员，我想导出/导入角色配置，以便新电脑或同事实时复用同一套角色 — v1

16. 作为手工测试人员，我想所有操作都是按钮点击、无任何命令行输入，以便零学习成本上手 — v1

19. 作为手工测试人员，我想临时沙箱窗口用完即毁（关闭后自动删除数据目录），以便测试未登录态/异常流程不残留数据 — v2

## Implementation Decisions

- **架构分层**：`chameleon-core`（Rust 库）承载全部领域逻辑；Tauri 命令层为薄壳透传，Web 前端无业务逻辑。核心库与 Tauri 外壳分 crate，外壳只调用库的公开 API（ADR-0002）。
- **角色模型**：`Role = { id, name, color, profileDir, cdpPort, quickLinks[] }`。`config.json` 为唯一配置源：角色列表 + 全局设置（浏览器路径、数据根目录、界面偏好）。明文 JSON，人工可改。
- **启动与端口**：每个角色启动时携带唯一 `--user-data-dir` + `--remote-debugging-port`（创建角色时自动挑选空闲端口并持久化，重启不变）；附加 `--no-first-run --no-default-browser-check`。Chrome 绑定 localhost 即可满足安全要求（ADR-0001）。
- **安全边界**：任何角色数据目录命中 Chrome/Edge 默认配置目录（如 `%LOCALAPPDATA%\Google\Chrome\User Data`）→ 拒绝启动 + 自然语言提示；一键关闭仅作用于测试数据目录；工具自身单实例锁（ADR-0003）。
- **便携布局**：exe + config.json + 数据根目录一个文件夹即可搬运；导出/导入 = 复制 config.json（ADR-0003）。
- **Handoff 语义**：读源角色当前激活标签页 URL → 目标角色新标签页打开并聚焦；每次操作呈现「并行打开 / 接力打开」两个按钮；接力模式用 CDP `Browser.close` 优雅关闭源窗口；目标未启动则先拉起。v1 仅传递激活标签页 URL（ADR-0001）。
- **错误处理**：统一错误码 → 自然语言文案映射层，所有失败路径出中文可读提示，无技术报错。
- **窗口位置记忆**（v1）：优先用 CDP `Browser.setWindowBounds` 在启动时恢复上次位置；Chrome 自带窗口位置记忆为兜底。
- **Sandbox**（v2）：临时数据目录 + 监听进程退出即删除 + 工具启动时扫描清理崩溃残留的孤儿临时目录。
- **Snapshot**（v2）：快照 = 每角色标签页 URL 列表 + 窗口位置，纯 JSON；恢复 = 启动角色 + 依次开标签。

## Testing Decisions

- **好测试的标准**：只测公开 API 的外部行为（启动参数正确性、CDP 握手、Handoff 结果、沙箱目录生命周期），不测内部实现细节；集成测试一律使用临时 profile + 随机端口，绝不触碰真实配置目录。
- **测试缝**：唯一缝 = `chameleon-core` 公开 API。Tauri 外壳与 Web 前端不自动化测试，手工验证。
- **测试形态**：
  - 单元测试：config.json 读写往返、端口分配、默认目录拒绝规则、导入导出、错误文案映射。
  - 集成测试：对真实 Chrome 运行——启动→CDP 连接→开标签→读激活标签 URL→优雅关窗→沙箱退出删目录。本环境已核实可驱动 Windows Edge / snap chromium。
- **框架**：标准 `cargo test`，不引入额外测试框架。
- **先例**：`inspect-tool` 的 lib+bin 结构与 chromiumoxide CDP 接线，测试沿用其模式。

## Out of Scope

- 账号同步 / 云服务登录
- 浏览器指纹隔离（仅会话级隔离，不做防关联/风控对抗）
- 自动化测试能力（不替代 Playwright）
- 权限配置 / 用户管理体系（工具本身免登录）
- Chrome 扩展级别的隔离
- v2 项（快照 / 沙箱 / 数据目录清理）不进 v1
- macOS / Linux 支持（v1 仅 Windows）
- 全部标签页传递、滚动位置传递（增强项，未排期）
